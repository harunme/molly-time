# MollyTime Android 家长端

Android 8.0（API 26）及以上的原生家长端，使用 Jetpack Compose / Material 3 和 Media3，独立于 `apps/tv/client` 电视端。默认连接 `https://mollytime.app`，与 iOS 共用账号、家庭及 Cookie / CSRF API。当前 iOS 源码是产品行为依据，规则见 [AGENTS.md](AGENTS.md)。

## 构建与运行

在仓库根目录执行：

```bash
bash tools/build-android.sh
```

入口复用仓库的 JDK 21 / Android SDK 36，校验并打包同源启动音效，运行单元测试、Android Lint 和 Debug 构建，输出 `artifacts/mollytime-android-debug.apk`。也可使用 Android Studio 打开 `apps/android`。

```bash
source tools/android-env.sh
adb install -r artifacts/mollytime-android-debug.apk
adb shell am start -n com.molly.parent.debug/com.molly.parent.MainActivity
```

Debug 包名为 `com.molly.parent.debug`，正式包为 `com.molly.parent`。已接入独立 APK 更新渠道和 CI 签名发布，不依赖应用市场。正式包与之前的 Debug 包是不同应用，首次安装正式包需要重新登录；此后同一包名、签名的覆盖更新保留数据。

## 与当前 iOS 对齐的实现

- 启动：同源品牌路径、1.8 秒动效及包内音效；系统 splash 退出后开始，不在启动时联网请求声音。会话恢复、首页获取并行，减少动态效果时显示静态标记，退后台停止且返回不重播。
- 加载与同步：180ms 延迟骨架、已有数据静默更新、资料库末尾自动分页、目录返回缓存、业务写入后自动失效。空间前台每 60 秒同步，电视状态在对应页面前台每 5 秒同步，后台停止轮询；旧账号和旧版本响应不能覆盖当前状态。
- 资料库：固定两列、最大宽度 700dp、20dp 间距；合集只显示封面与居中名称，视频显示时长和观看状态。没有自行增加的搜索、常驻刷新、手动目录分页、合集副标签或封面角标。保留 iOS 的下拉更新和错误后的重新加载。
- 资源：独立视频详情、家长播放、重命名、更换封面、移动、开放／隐藏、归档；长按菜单、拖动排列及无障碍上移／下移。排序只提交相邻资源锚点，编辑时延后自动刷新，保存失败重读真实顺序。
- 上传：相册视频准备为 H.264 / AAC MP4、文件选择器导入 MP4、名称／合集／处理后允许孩子观看选项、明确开始上传。按账号保存草稿和服务器上传 ID，恢复时读取服务器偏移或已确认 OSS 分片；失败保留任务，支持暂停、继续、检查处理、重试处理及重试开放。取消临时上传后保留已创建的待完善资源。Android 原生前台服务支持离开页面、锁屏和切换 App 后传输，系统通知显示进度。
- 播放：家长手机播放不占儿童额度。原生播放器保留旋转前的进度、暂停状态、倍速和字幕选择，每五秒保存本机续播，接近结尾清零；支持 10 秒快进／后退、拖动进度、适应／铺满画面和重新获取播放地址。使用服务端已调整偏移的字幕，不再过滤非零 offset 的轨道。
- 缓存：按服务、账号、媒体 ID、版本、大小与 MIME 隔离视频缓存；256KiB 按需分块、SHA-256 校验、原子落盘、重复请求共享传输。不保存签名 URL，不预下载整部视频，不自动清理观看缓存；服务器不支持 Range 时回退普通播放。封面缓存限 200 项／64MiB 内存，只有带版本的封面可写 64MiB／7 天磁盘缓存，失败保留已有图像。
- 账号：邀请码预览与注册、注册结果不确定时先尝试登录，避免重复激活；多个加密保存的账号、切换、过期重登和移除本机记录。新账号认证成功后才切换，当前未完成上传会暂停，切回可以继续；不保存密码。
- 我的：真实头像和名称入口、个人资料编辑、账号 ID 复制、修改登录密码、切换账号、退出；空间含上传预留，最近删除、播放偏好、观看说明与免责条款。删除任务异步轮询，支持恢复／重试，刷新保留已加载页。
- 电视：绑定码／当前服务配对链接／二维码扫描，查找后确认绑定；完整设备分页、观看安排、首次家长 PIN、加看、结束今天观看、这集看完休息、重命名和解绑。只有观看安排的 409 才重新基于服务器状态确认，普通资源冲突直接显示原错误。保留分钟／集数各自编辑值。
- 提醒与报告：默认字幕、重设家长密码，最后一集／该休息了两种提醒视频、当前提醒预览与替换；12 周热力图与今日光晕，今日／近七天汇总、小时／日分布、设备时长、可展开的播放明细／内容分布、分页和最后同步时间。

## 安全边界

权限、归属、额度和观看规则由服务端裁决。凭证请求限定当前 HTTPS origin 的 `/api/`，拒绝重定向；外部 OSS 媒体和上传签名请求不携带家长 Cookie、CSRF 或 Authorization。账号会话使用 Android Keystore AES-GCM 加密；禁用云备份和设备迁移，媒体缓存和上传草稿放在不备份目录。保存的页面导航不包含 Cookie、CSRF 或密码，不记录签名 URL 或凭证日志。

## 尚存的平台差异与发布验收

不能把这一轮实现和模拟器检查等同于所有设备、所有流程已经完成验收。

- iOS 播放器使用系统 AirPlay；Android 当前没有对应的远程投播入口，电视绑定与观看控制仍使用同一业务协议。未增加一个无法完成投播的占位按钮。
- Android 上传使用系统前台服务；用户强制停止应用后，需要再次打开应用并恢复登录才能恢复任务。Android 15+ 前台服务超时会暂停并保留草稿；进程被回收后的系统重启时机与 iOS 后台上传机制不同。
- 发布前需在真实 Android 设备验证相册编码、相机授权／扫码、不同编码和长视频、弱网／锁屏／进程回收后的上传与恢复，以及多账号、异步删除和真实电视控制的完整写入流程。邀请码激活和真实 OSS 上传尚未在生产账号执行验收。

## APK 更新与流水线

「我的 → 版本更新」支持手动检查；冷启动在初始页面就绪后静默检查，有新版才提示，播放和其他详情／操作页面期间延后展示。下载、校验、安装均由用户确认。首次安装前通过 Android 系统设置授权“安装未知应用”，之后交给系统 PackageInstaller 覆盖安装，不能承诺静默安装。

更新请求不携带家长凭证。先检查包名、递增构建号、系统要求和最大大小，再校验实际 APK 长度与 SHA-256；服务端验证证书连续性，Android 系统最终检查覆盖兼容性。下载失败重新检查当前发布版本，取消保留旧应用；取消检查后的迟到响应不会重新打开提示。旧 API 不支持更新时不阻止启动。

本地正式出包：

```bash
bash tools/build-android.sh release
```

签名复用现有 TV 工程的 `.local/signing/release.properties`，也可通过 `MOLLYTIME_SIGNING_PROPERTIES` 指定同格式文件；缺少签名时正式构建明确失败。版本默认值在 `app/version.properties`，CI 通过 `mollyVersionCode` / `mollyVersionName` 注入发布版本。私钥和密码不进入源码或 APK。

仓库 `.github/workflows/deploy.yml` 对 TV 和家长端分别读取已发布历史与输入指纹。家长端使用 `com.molly.parent`、`artifacts/parent-client-plan.json`、`tools/parent-apk-build.json`。有原生变更才构建、测试、Lint、签名；构建号高于全部历史版本，名称遵循现有按月发布规则，支持 `force_parent_apk` 手动重建。共享构建工具变化可能同时触发两个客户端。

CI 复用现有四个 `MOLLYTIME_TV_*` 签名 Secrets，正式包输出 `mollytime-android-release.apk` 并归档到 Actions 的 `mollytime-android-<构建号>` artifact，保留 30 天。发布包携带家长端 APK 与计划，经固定接收器校验提交、渠道、指纹和版本基线后复用发布工具，存入私有 OSS 或当前渠道所用服务器存储。APK 存储沿用 `releases/tv/<包名>/…` 前缀以兼容现有 OSS 权限，包名仍严格隔离。

首尔固定 CI 接收器支持只读 `parent-apk-state`；升级工具为 `python3 tools/setup_parent_ci.py`，仅通过现有管理密钥安装固定脚本，持有部署锁、保留备份，并验证 TV 状态不变，不重启容器。上传发布包不能修改这些固定脚本。

更新服务：`GET /api/client/releases/latest?packageName=com.molly.parent`；Debug 使用 `com.molly.parent.debug`。运营后台的客户端版本列表支持两个客户端各自的正式／Debug 渠道。命令行手工发布仍使用通用实现所在的 `mollytime_server.scripts.publish_tv_release`；名称保留兼容，验证已扩展到家长端。

CI 正式生效需要把代码推送到 `main`；该工作流会同时部署生产 API 和网页，APK 在服务健康检查通过后发布。固定接收器升级与本地出包不等于已经完成首次 CI 发布。系统安装授权、取消和覆盖后的实际保留仍应在真实设备完成验收。
