# 观看安排

每台电视独立设置，每次选择“按集数”或“按时间”。默认关闭，升级不会改变原有播放方式。暂不提供每日额度、定时开放或儿童独立额度。

## 家长操作

管理后台「家庭设置 → 观看管理」集中配置观看规则、家庭共用的四位数字家长密码、播放偏好和提醒视频。概览保留允许观看、加看和休息快捷操作，并提供「观看设置」入口。电视关机或尚未上报客户端能力时，也可开启、修改并保存观看管理；后台显示已保存、待电视同步。每次可选 1、2、3 集，或 15、30、45、60 分钟，支持自定义。保存只是设置平时的安排；点击「允许观看」才开始本次观看，仍由孩子主动选片。

TV 的「这次看多少」只提供两排选项：1、2、3 集，或 15、30、60 分钟。不需要切换观看方式，默认选中上次使用的预设数量（后台自定义数量不在预设内时默认 2 集）。选择后点击「开始观看」，输入四位家长密码后自动确认并返回视频首页。首次使用时在同一页设置家长密码；已有密码只能由后台管理员重设。TV 不提供自定义、固定片单、重新选片或关闭管理等操作；更多设置在后台完成。

「开始观看」在一次命令内保存数量、开启管理并发放本次额度，替换之前的安排；需要家长密码及网络。输入不足四位不执行，相同请求重试不重复发放。密码连续输错五次锁定五分钟。普通家庭成员只查看，不能控制后台安排。

按集数时，自由点视频、换视频或重播，不限制文件夹和顺序。完整播放一集扣一集，暂停、中途换片不扣集数；重播并完整看完仍算一集。按原有播放顺序自动连播，到达本次集数后休息。后台「再看一集」增加本次一个额度；TV 需要继续观看时，重新选择本次数量并输入密码。

按时间时，可以自由选片，点播、直播、下载到电视的视频共用实际播放时间。暂停、缓冲、选片、关机和家长提醒视频不计时。时间到暂停并保存进度；「再看 10 分钟」只增加本次时间，不改变平时设置。直播仍保留单次最长 30 分钟保护；按集数的安排不能播放直播。

「看完这集休息」取消后续集，未开始时允许接下来一集。「现在休息」立即停止并结束本次安排。结束后不会自动恢复；重启软件、电视、服务端或跨天均不增加额度。

## 提醒、离线与同步

最后一集及剩余五分钟会提示。家庭设置里已有的剩一集、休息视频可以继续使用；没有视频或加载失败时使用系统文字，限制始终生效，提醒不计时。

原生客户端本地保存已确认额度与消耗，断网也可自由播放已有离线副本的内容，并按集数或时间限制。新增授权和加看需联网。记录缺失、损坏或存储失败时要求联网恢复，不自动放行。

时间限制由播放器单调时钟执行，最多提前保存一秒额度；正常暂停退回未播放部分，异常退出最多额外扣除一秒。观看统计仍使用独立的实际播放区间，不使用预扣值。

后台操作离线设备时显示待同步。正常联网的设备在五秒内同步，设备上报确认版本后才显示已确认。服务器按设备保存版本及幂等命令，迟到的旧观看记录不会消耗新安排。

浏览器 TV 支持在线预览、计时和刷新后恢复；离线播放保障由 Android 原生客户端承担。浏览器本地记录与 API 同步，存储失败时停止播放。

## 接口与兼容性

- `GET /api/manage/watch-control`：家庭设备设置、当前安排、确认版本及密码是否已设置。
- `PUT /api/manage/watch-control/pin`：管理员设置/重设密码。
- `POST /api/manage/watch-control/{device_id}/commands`：后台操作。
- `GET /api/watch-control`：当前 TV 状态。
- `POST /api/watch-control/sync`：能力登记、安排消耗同步及版本确认。
- `POST /api/watch-control/commands`：输入 PIN 后的 TV 操作。
- `POST /api/watch-control/pin`：首次设置家庭 PIN，已有 PIN 时拒绝覆盖。

命令包含 `requestId`、`version`、`action`；动作包括 `settings`、`allow`、`add`、`stop`、`finish-current`、`start`；旧 `reselect` 命令保留兼容。`start` 在一次事务内保存数量并发放本次额度。设置和开始额外包含 `enabled`、`mode`（`episodes`/`minutes`）、`amount`。TV 命令同时携带 PIN。相同请求重试不重复执行，版本过期返回 409。

新表通过现有数据库初始化流程创建，不改写历史观看记录。服务端先部署，后台配置不依赖电视在线或能力登记。电视开机联网后取得已保存的规则，支持 `watchControl` 的客户端执行并确认；旧客户端需升级后执行，后台不会显示已确认。旧提醒未结束时需先处理原提醒；开启管理后旧恢复接口无法绕过限制。

## 验证

服务端 `test_watch_control.py` 覆盖自由换片、完成计数、续播、加看、计时耗尽、权限、密码限流、设备隔离、原子开始、幂等、版本冲突和离线补传。后台 `watch-control.spec.ts` 使用临时 API 和真实视频验证两端流程、六个 TV 预设、四位密码自动提交和上次选择记忆。原生 `WatchControlTest` 覆盖计时、暂停、异常恢复、状态合并和绑定隔离。

发布前还需在真实电视验收 Bridge、遥控器、点播、直播、下载播放、断网和重启。日常测试不启动 Docker、模拟器或 Android 客户端。
