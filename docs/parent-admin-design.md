# Molly 家长管理后台设计

日期：2026-10-12。状态：设计基线，基础管理页面与接口已实施；实际范围、设计差异和运行方法见 [后台说明](../apps/parent-web/README.md)。

## 1. 产品定位与入口

让家长完成三件事：**把资源放进去、安排孩子看到什么、了解实际播放了多久**。

后台以家庭为单位，电脑适合批量上传与编排，手机适合查看记录、发布和调整内容。默认打开资源库；不单独建设只有指标卡片的总览页。与 TV 共用一个 FastAPI 服务、数据库和媒体目录，管理网页部署在 `/manage/`，TV 网页继续位于 `/tv/`。

第一版导航：**资源库 / 上传任务 / 首页编排 / 观看记录 / 家庭设置**。同一账号可管理自己的家庭；平台级多租户运营、收费和推荐算法不属于本次范围。

## 2. 页面与主要操作

| 页面 | 内容与主要操作 |
| --- | --- |
| 资源库 | 按系列显示封面、已发布/草稿集数；搜索，筛选状态；上传、新建系列、编辑封面与介绍、批量发布/下架 |
| 系列详情 | 系列信息、季和剧集列表；改集数、排序、字幕、封面；预览、替换文件、发布/下架；显示文件检查结果 |
| 上传任务 | 当前与历史批次；逐文件上传进度、处理状态、错误原因、恢复上传、重试处理、取消 |
| 首页编排 | 家庭默认首页与儿童独立首页；编辑栏目、选内容、调顺序；TV 比例预览、保存草稿、发布、恢复历史版本 |
| 观看记录 | 儿童与日期筛选；实际播放时长、每日趋势、内容分布、播放明细；显示同步状态与统计起始日期 |
| 家庭设置 | 儿童档案、TV 设备绑定与撤销、家庭时区、账号密码；资源占用与可用磁盘空间 |

不在资源页重复播放器内部参数。编码不支持、文件损坏等问题用可理解的提示说明，诊断信息收在展开区域。

## 3. 上传与资源发布

### 家长操作流程

1. 进入已有系列，或填写新系列名称；单个视频也可放在只有一集的系列中，继续复用当前目录层级。
2. 选择多个视频。字幕和封面可以同时选入；首版通过文件名规则给出匹配建议，家长确认歧义。视频原始文件名保留在详情中。
3. 在上传前核对每行的剧集名、季、集数和配套文件。序号冲突、同名资源给出明确选择，默认不覆盖已有内容。
4. 开始上传。允许离开当前页；同一浏览器重新进入时可继续上传，但浏览器被关闭后不会继续后台传输。需要重新选择文件时按文件指纹核对。
5. 服务端检查视频、读取时长、生成封面、验证字幕；完成后得到可预览的草稿。家长确认并发布，TV 才能看到。

```text
文件状态：待上传 → 上传中 → 已接收 → 检查中 → 就绪
                    ↘ 上传失败       ↘ 检查失败
内容状态：草稿 ──发布──→ 已发布 ──下架──→ 草稿
                 ↑                         │
                 └────────重新发布─────────┘
内容可另行归档，归档后不出现在普通资源列表和 TV 中。
```

上传成功不等于可以播放，也不等于已经发布。列表分开显示传输、处理和发布状态；只有文件就绪且内容已发布的剧集进入 TV 目录。系列、季的展示与集数只计算符合条件的剧集。

### 最小技术方案

- 本地存储优先。浏览器按块上传，服务端保存已接收偏移；每个上传独立 ID，重复提交同一块可安全重试。初始块大小 8 MiB、同时上传 2 个文件，后续根据设备调整。
- 完成接口校验大小和校验和，原子转入媒体目录，再创建持久化处理任务。任务带重试次数与执行租约，服务重启后可恢复；接口与工作进程共享数据库，不加 Redis/Celery。
- 媒体检查使用 FFprobe，封面使用 FFmpeg。首版优先验收 MP4（H.264/AAC）和 SRT/VTT；扩展名不等于编码兼容，是否支持仍以目标 TV 实测为准。不支持的文件保留草稿并说明原因，不默认转码。
- 视频、字幕和封面各自限制大小；磁盘不足时禁止继续上传，过期未完成的上传可清理。对外不接受任意服务器文件路径。
- 替换视频保留剧集 ID，新增媒体版本；确认新文件就绪后再切换。已开始的播放会话继续使用旧版本，旧文件在会话结束和保留期后清理。视频变短时续播位置按新时长约束。
- 下架先阻止新的浏览和播放，已开始的播放默认允许结束。归档、永久删除是不同操作；永久删除需显示影响范围并确认，历史记录保留剧集名快照。

视频统一通过管理后台上传，不提供服务器本地目录扫描导入；目录归属和发布状态由家长管理。

## 4. 首页编排

采用**受约束的栏目编辑器**，每个栏目是 TV 上的一条横向内容行。首版提供三种来源：

| 栏目 | 配置 |
| --- | --- |
| 继续观看 | 当前儿童未完成的剧集，按最近播放排序；家长只改标题、开关和条数 |
| 手选系列 | 家长选系列并排序，如“英语启蒙”“睡前故事”；点击进入系列详情 |
| 最近发布 | 按首次发布时间倒序的系列，限制条数；重复编辑不改变首次发布时间 |

首版统一系列卡片样式，不做自由画布、任意 HTML、广告位或轮播大屏。手选剧集栏目等 TV 支持对应卡片和焦点行为后再加入。

```text
首页编排    对象：[家庭默认 ▾]       状态：草稿   [保存] [发布]
┌──────────────────────┬─────────────────────────────────┐
│ 栏目顺序              │ TV 预览 · 16:9 · 儿童：小米 ▾     │
│ ↕ 继续观看      开启   │                                 │
│ ↕ 英语启蒙      开启   │ 继续观看   ▣  ▣  ▣               │
│ ↕ 最近发布      关闭   │                                 │
│ [+ 添加栏目]          │ 英语启蒙   ▣  ▣  ▣  ▣            │
│                      │                                 │
│ 当前栏目：英语启蒙    │ [模拟遥控器浏览]                   │
│ 标题 [英语启蒙    ]   │                                 │
│ 内容 [选择系列]       │                                 │
└──────────────────────┴─────────────────────────────────┘
```

- 家庭默认首页对所有儿童生效。儿童默认“跟随家庭”；选择“独立配置”时复制当前家庭版本，此后独立维护，可切回跟随。预览须选儿童，才能显示对应续播与可见内容。
- 草稿不影响线上；发布生成不可变版本，带 `schemaVersion` 和修订号。保存采用乐观锁，冲突提示重新加载；恢复历史版本也生成一个新发布版本。
- 发布时校验引用属于当前家庭、内容可发布、栏目数量与条数在上限内。运行时再次过滤下架或不可见资源，空栏目隐藏；全部为空时提供“还没有可观看内容”的空态。
- TV 进入或返回首页时获取新配置；正在播放时不刷新网页或打断播放。接口解析配置并返回 TV DTO，TV 不解释原始后台编辑数据。
- 系列栏目保持现有 `rows/title/items` 展示契约；继续观看需同步更新 TV 的剧集卡片和接口能力声明。未声明新能力的客户端只返回系列栏目，不能让旧客户端把剧集误当成系列。新客户端对未知栏目类型跳过，保留可识别栏目；能力协商方式在实现时与 Bridge 白名单一起确定。
- 编辑预览复用 TV 的卡片、布局与焦点组件，通过预览适配器接收草稿数据；播放预览使用家长身份，明确标记并排除儿童统计。无需让管理页拥有原生 Bridge 权限。

首页配置决定展示顺序；如果要限制某个孩子可看的内容，应另设儿童内容规则，并在目录、详情、视频、字幕与封面接口共同校验。第一版默认儿童可看家庭所有已发布内容，不把“首页没放这部片”解释为禁止观看。

## 5. 观看记录与统计口径

### 页面

默认查看一个儿童近 7 天；可切换今天、近 30 天、自定义日期和全家庭。页面显示：

- **实际播放时长**、**播放过的剧集数**、**最后同步时间**。
- 每日播放时长柱状图；按系列汇总的时长列表。
- 会话明细：开始时间、儿童、设备、内容、实际播放时长、结束位置、结束原因与同步状态。

所有样例数据须标注“示例”；未接通上报时显示“统计尚未启用”，不填假数据。旧记录只用于续播，页面标明正式统计起始时间，历史不可统计时段不显示成 0 分钟。

### 口径

**观看时长 = 原生播放器处于实际播放状态时经过的真实时间。** 暂停、缓冲、拖动、后台暂停不计入；重复观看计入，2 倍速播放 10 分钟仍记 10 分钟。它反映设备播放时间，不能证明孩子一直在看屏幕。

`positionMs` 是续播位置；`mediaDurationMs` 是视频总长度；`playedMs` 是实际播放累计时间，三者独立。不能通过播放位置相减、视频长度相加或旧事件数量推算观看时长。“播放过的剧集数”计算区间内存在有效播放时间的不同剧集；不以拖到片尾作为观看完成率。

### 上报与存储

1. 原生创建会话，绑定设备、儿童、剧集和媒体版本，区分 `child_watch` 与 `parent_preview`。切换儿童或剧集必须开启新会话。
2. 使用单调时钟记录播放区间，在 `isPlaying` 状态变化、进入后台、结束时结算；每 15 秒上报一次。上报含 `sessionId`、递增 `seq`、区间起止偏移、实际播放毫秒、结束位置和状态。
3. 服务端以 `(sessionId, seq)` 唯一约束去重。逐区间验证非负、时间上界和重叠；重复/乱序请求不增加统计，不让旧会话补传覆盖新会话的续播位置。
4. 服务端在创建会话时提供时间锚点，以客户端单调偏移定位区间；时间异常标记待检查，不把收到请求的时间当作实际播放时间。失去锚点时仍保留有效总时长，并标记日期归属不确定。
5. 失败事件保存在原生有限队列中，联网补传，服务端确认后清除。崩溃前未落盘/未上报的时间不补猜，明细标记会话未正常结束。
6. 按家庭时区（默认 `Asia/Shanghai`）拆分跨午夜区间，使用半开日期范围。报表显示所用时区；改时区后按新时区重新汇总，原始时间不改写。
7. 多台设备分别累计；全家庭和同一儿童汇总可能包含同时播放，界面注明“按设备播放时间累计”。第一版不推断唯一注意力时长。

先对有索引的会话区间做数据库聚合，支持按儿童、日期、系列和设备筛选。数据增长后再建立可重算的日汇总，不增加统计服务。旧 `PlaybackEvent` 不迁移成虚构的播放区间。

## 6. 数据与接口边界

### 在现有模型上增量演进

| 模型 | 变化 |
| --- | --- |
| `Family / User / ChildProfile` | 延续家庭归属；增加家庭时区、儿童档案管理；管理接口校验家长角色 |
| `Item / MediaFile` | 增加内容状态、首次发布时间、归档时间、媒体版本与处理状态；保留现有资源 ID 和层级 |
| `UploadSession / MediaTask` | 上传偏移、文件指纹、状态、失败原因；持久化可恢复的检查/封面任务 |
| `HomeConfigRevision` | 家庭或儿童作用域、草稿内容、修订号、已发布版本指针、操作者与发布时间 |
| `Device / PlaybackSession / PlaybackInterval` | 可撤销设备身份、会话时间锚点、上报序号、播放区间和诊断状态 |
| `PlaybackProgress` | 按儿童与剧集的续播投影，明确排序规则，防止迟到事件倒退进度 |

引入版本化数据库迁移，迁移前备份 SQLite；现有 `create_all()` 不会给旧表添加这些字段。已有扫描资源须先核对文件并由家长确认发布，不能简单把所有旧 `Item` 设为已发布。归属为空的数据先修复归属，不能透过管理接口跨家庭展示。

### 接口分组（拟定）

| 接口 | 职责 |
| --- | --- |
| `/api/manage/resources`、`/resources/{id}` | 查询资源、编辑元数据、草稿管理 |
| `/api/manage/resources/{id}/publish`、`/unpublish`、`/archive` | 状态切换，批量操作返回逐项结果 |
| `/api/manage/uploads`、`/{id}`、`/{id}/chunks`、`/{id}/complete` | 建立上传、查询偏移、上传块、提交检查任务 |
| `/api/manage/tasks`、`/{id}/retry` | 处理状态与重试 |
| `/api/manage/home-config`、`/preview`、`/publish`、`/revisions` | 草稿、预览、发布和版本历史；作用域参数只接受本家庭儿童 |
| `/api/manage/reports/watch-time`、`/sessions` | 汇总和明细，统一使用明确的日期范围与时区 |
| `/api/manage/children`、`/devices` | 儿童管理、绑定设备、撤销设备 |
| `/api/playback/sessions`、`/{id}/events` | 原生播放会话与幂等上报 |
| 现有 `/api/home`、目录与媒体接口 | 返回已发布、可播放且身份有权访问的资源 |

管理 API 与 TV API 共享业务模块和数据库。家庭 ID 来自登录身份，所有资源/子档案/设备 ID 再做归属校验；管理接口不进入 TV Bridge 白名单。TV 绑定后只获得浏览、播放和自身上报权限，不能用管理员凭证调用管理操作。

管理网页与 API 同源。家长网页采用 HttpOnly 会话 Cookie、写操作 CSRF 校验与来源校验；原生继续使用自己的授权头。刷新凭证不放入浏览器 localStorage。角色首版只提供管理员和可查看记录的家长成员，不做复杂权限编辑器。多家庭账号登录在扩展前须解决现有按用户名查询、但用户名只在家庭内唯一的歧义。

## 7. 工程组织与上线顺序

```text
apps/parent-web/             React + TypeScript + Vite；构建后静态部署
apps/tv-web/                 TV 页面；复用展示组件与 DTO
apps/tv/client/              原生播放器、设备身份、正式播放区间上报
apps/server/molly_server/    manage、uploads、home_config、reporting 等模块
同一个 HTTPS 入口 → 同一个 FastAPI 服务 → SQLite + 本地媒体
                                       ↘ 同项目媒体任务工作进程
```

TV 组件真正需要复用时再抽小型共享包；管理表单、桌面导航不用 TV 的遥控器组件。不加常驻 Node 服务、微服务或通用 CMS。

| 批次 | 交付与验收 |
| --- | --- |
| 1：资源闭环 | 登录、资源库、批量可恢复上传、检查任务、草稿/预览/发布/下架；发布后 TV 可播放；断网重试、任务重启、跨家庭访问、磁盘不足有明确结果 |
| 2：首页闭环 | 栏目编辑、儿童跟随/独立、预览、版本发布/恢复；TV 返回首页更新，旧版 TV 兼容，已下架引用不再展示 |
| 3：统计闭环 | 设备绑定、原生区间上报、观看记录页；验证暂停、缓冲、拖动、倍速、重复上报、乱序补传、跨日和并发设备；旧数据明确不可统计 |

观看记录入口可以先展示说明空态；只有原生上报与统计校验一起完成才发布真实报表。第一版完成上述三批次；标签筛选、儿童内容限制、观看时长限额、自动转码、OSS/CDN 和消息通知随后按实际需求追加。

实现前的实机门槛仍是华为 V65 的网页、遥控器和编码兼容验证。管理后台的设计可以独立推进，但不能把后台文件检查成功等同于实机播放验收。

## 8. 判断分工

权限、上传校验、资源状态、发布校验、事件去重与统计计算由确定性代码处理；Codex 负责本设计与后续实现。本阶段文件匹配采用规则与人工确认，不引入语义模型。

Jev usage: Not used。本任务属于架构与交互设计，没有需要 Jev 的有界语义判断。
