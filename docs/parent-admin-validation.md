# 家长管理后台基础版验证

日期：2026-10-12。

## 自动检查

- 服务端 30 项测试：本地 Range 保持兼容；家庭与草稿访问隔离、Cookie/CSRF/来源校验；真实 MP4 分块续传、丢失应答后的重复块、文件处理与封面、失败重试；首页草稿/发布/儿童继承/修订冲突；观看区间去重、暂停和拖动口径、并发重叠拒绝、乱序补传、跨午夜统计；设备撤销、角色约束、重复初始化、新扫描草稿与封面替换；本机 Origin 丢失端口时的同源证据与拒绝分支。
- 家长网页 2 项真实服务操作测试：上传 → 检查 → 预览 → 发布 → 首页草稿/发布；设备上报 → 报表 → 儿童新增 → 390px 手机布局 → 撤销设备。使用临时数据库，不修改现有家庭。
- TV 网页 3 项测试：遥控器焦点、路由返回、播放返回、退出、登录失败恢复；新版多行滚动、跨行焦点记忆、弹层边界与 TV 分辨率，见 [TV 界面设计](tv-interface-design.md)。
- Android 5 项单元测试：3 项 Bridge 路径策略、2 项实际播放时钟测试；APK 构建与 lint 检查。

总计 40 项自动测试；原生实播和容器启动另行验证。

浏览器登录回归：用户 Chrome 页面 `http://127.0.0.1:8099/manage/` 的 Origin 被改成无端口的 `http://127.0.0.1`。本机兼容分支同时要求 `Sec-Fetch-Site: same-origin` 与完全匹配的 Referer；外站、不同显式端口、非本机地址、缺失证据和畸形输入继续拒绝。已在用户浏览器使用默认账号登录并确认资源库显示。

服务端测试使用运行环境同款 SQLite 引擎，开启外键与 WAL；不是在关闭约束的测试库上通过。

## 容器

最终镜像 `molly-server:management` 构建与启动通过。使用临时数据库初始化管理员后，`/healthz`、`/tv/`、`/manage/` 均返回 200，管理 Cookie 登录、会话读取与 CSRF 校验后的儿童创建通过。FFprobe 已安装，SQLite 实际配置为 `foreign_keys=1`、`journal_mode=wal`；compose 配置校验通过。

## 原生实播

使用已有媒体库的隔离 SQLite 副本、Android TV API 34 模拟器、新版 APK，选择“验证儿童”并播放实际 Hello 视频。

- 登录、目录、原生视频画面、返回网页焦点和 API 白名单验证通过。
- 一次基础实播收到约 5.5 秒有效播放时间。
- 暂停/恢复验证会话的区间如下，单位为毫秒：

| 开始 | 结束 | 有效播放 |
| ---: | ---: | ---: |
| 0 | 992 | 0 |
| 992 | 7580 | 6588 |
| 7580 | 12526 | 0 |
| 12526 | 15285 | 2759 |
| 15285 | 16192 | 907 |
| 16192 | 16731 | 0 |
| 16731 | 16731 | 0（结束事件） |

最终交付 APK 的约 4.9 秒暂停区间被排除，总有效播放 10254ms；准备视频和后台暂停的时间也不计入。脚本读取 debug 日志中的实际 `isPlaying`，确认播放 → 暂停后四秒持续不播放 → 恢复播放，并验证退出后的焦点。验证使用播放器的空格播放/暂停控制；系统按键可能被拦截，不能仅凭发送了按键就断言已经暂停。
