# 客户端错误上报

各端共用 `POST /api/client/error-logs`。平台超管在管理后台「系统日志 → 客户端异常」查看，可按客户端和异常级别筛选，展开异常栈及最近操作。原有电视播放错误仍显示在同页的「设备错误日志」。

## 采集范围

| 客户端 | 采集内容 | 补传方式 |
| --- | --- | --- |
| 安卓家长端 | Java/Kotlin 未捕获异常、关键业务及播放错误、封面保存错误 | 崩溃处理器同步原子落盘，保留系统原有崩溃处理；下次启动并恢复原账号后补传 |
| 安卓电视端 | Java/Kotlin 未捕获异常、WebView 渲染进程退出 | 原子落盘和独立后台重试，不阻塞播放或配对请求 |
| 两个安卓端，Android 11 及以上 | 系统记录的本进程崩溃、原生崩溃、ANR、低内存退出 | 启动时读取最近一次进程退出信息；系统退出记录仅有原因和状态，不保证包含异常栈 |
| iOS 家长端 | Objective-C 未捕获异常、MetricKit 崩溃报告、API 传输／解析／服务端错误、封面准备错误 | 本地持久队列；MetricKit 由系统延迟投递，不能保证重启后立即获得报告 |
| 网页管理端、电视网页 | 全局脚本异常、未处理 Promise rejection、React 异常 | 持久队列，恢复连接、回前台、恢复登录和每分钟补传 |

安卓封面流程记录 `cover.selected`、`cover.enqueue`、`cover.enqueued`、`cover.saved`、`cover.acknowledged`；点击根 tab 时先记录 `tab.select.0/1/2`，再更新界面。这样即使在列表销毁过程中崩溃，也能看到导致退出的操作。

## 数据与边界

- 上传事件 ID、端类型、构建版本、系统和设备型号、异常类型、最多 64 行栈帧，以及最多 20 条固定名称的操作记录。事件时间和服务器接收时间分别保存。
- 客户端不采集异常消息、请求内容、用户输入、媒体名和完整 URL。网页只保留栈帧中的脚本文件名及行列号；服务端再次移除 URL、邮箱和常见认证字段。
- 本地最多保留 32 条日志，优先保留崩溃；保留原事件 ID 重试。短时间重复的已捕获错误会去重，失败后至少间隔约一分钟重试。
- 本地记录按服务器和账号／电视绑定隔离，只有原归属恢复认证后才能发送；未认证的首次启动不进行匿名上报。iOS 系统报告覆盖时间段内若发生账号切换，放弃无法明确归属的报告。
- 家长会话沿用同源 Cookie 与 CSRF，普通家庭成员也可上报自己的异常；电视沿用可撤销的设备凭证。归属由服务器认证决定，请求体不能指定家庭或用户。
- 后台查询仅平台超管可用。每个家长账号、每个电视绑定每小时最多接收 120 条，日志 ID 幂等；服务端接收后保留 30 天。原有电视播放日志继续使用每小时 60 条的规则。
- Android 10 及更早版本的原生信号崩溃、ANR 和低内存杀进程无法依赖系统退出接口补录。iOS 栈帧需要保留对应发行构建的 dSYM 才能完整符号化。
- 代码部署到后台并更新对应客户端后才开始采集，不能恢复接入前已经丢失的闪退日志。

## 验证

后端测试覆盖认证、CSRF、成员上报、超管查询、电视归属、账号冲突、脱敏、字段上限、限流和清理；安卓测试覆盖崩溃落盘、系统处理器调用、重启后重试、账号隔离和队列上限；浏览器测试使用隔离数据库验证异常进入后台、移动端查看、断网补传和切换账号时不串报。

日常检查无需启动安卓客户端或模拟器。出包分别使用 `tools/build-android.sh`、`tools/build-tv-client.sh` 和 `tools/build-ios.sh`；安装新包后，应在测试账号上制造异常并核对后台事件。
