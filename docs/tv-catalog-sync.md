# TV 本地目录与离线播放

TV Shell 使用原生 SQLite 保存内容目录，网页通过 Bridge 读取本地页。目录数据与观看进度使用独立版本，进入页面和播放返回不再等待远程列表刷新。普通浏览器预览、旧客户端及不支持同步接口的旧服务端继续使用原有分页接口；离线能力需要新版 Android Shell。

## 同步协议

- `/api/tv/sync-state`：设备鉴权后的目录、首页、播放状态、策略版本及签名离线授权。前台每 60 秒检查；启动、恢复前台、网络恢复触发检查，10 秒内合并。未改变的内容版本不重新拉取 manifest、目录页或已有封面。
- `/api/tv/catalog/manifest?version=...`：文件夹 ID、独立版本及视频总数。
- `/api/tv/catalog/home?version=...&page=...&pageSize=48[&rowId=...]`：静态首页栏目。
- `/api/tv/catalog/folders/{id}?version=...&page=...&pageSize=48`：静态视频目录。
- `/api/tv/playback-state`：最近播放及进度，含会话和序号，用于确认本地观察已上传。
- `/api/tv/offline-events`：每批最多 20 个离线会话，每会话最多 100 条事件；服务端复用已有幂等和“较新会话优先”的观看记录规则。

所有快照读在独立一致性事务内进行。分页请求版本过期返回 409，客户端重新检查版本，不把不同版本的分页拼接在一起。内容版本在同一个写事务中更新，回滚不更新版本；播放进度不使静态目录失效。首页草稿编辑不使已发布首页失效。SQLite / MySQL 使用各自的原子 upsert，只新增 `tv_catalog_versions` 表。

## 客户端调度与存储

启动延迟 1 秒后开始同步。后台一次拉取一页，页间隔 250 毫秒；打开的文件夹优先，其次首页剩余页，再到其他文件夹。即使用户不下滑，也会继续同步整个目录。网络失败按 5 秒、15 秒、60 秒、5 分钟退避；恢复网络可提前唤醒检查。播放及应用退到后台暂停元数据与封面预取。

每个媒体库 / 设备绑定使用独立数据库。分页检查点持久化，重启继续同步。文件夹完整后切换版本，首页所有栏目完整后统一切换；更新期间继续读取最后完整版本。首次同步允许读取已落盘页，未到达的页返回 pending。下架文件夹立即从本地 manifest 和目录移除。

元数据预算 128 MiB；封面最多两个并发、最多 128 个排队任务，每个绑定目录采用 256 MiB LRU，并保留至少 1 GiB 可用磁盘空间。封面按绑定、图片路径和内容哈希缓存，服务器返回的图片版本必须匹配才能落盘。预算不足时保留可用快照并显示同步错误。封面预算不足以容纳全部图片时，离线可显示文字占位。已成功预取过的图片版本记录在本地；被 LRU 淘汰后不会在后台循环下载同一版本，避免缓存预算不足时持续请求。

网格及横向列表使用虚拟化，只挂载可见项、邻近区域和当前 / 待移动焦点。方向键按逻辑索引移动，返回时恢复焦点及滚动位置，未挂载卡片不参与全量布局测量。

## 离线播放

自动同步目录和封面不会自动下载视频。视频仍由已有的“保存到电视”流程下载。下载完成后保存播放描述和字幕；仅完整且经过服务端 SHA-256 校验的精确媒体版本可离线播放，并显示“可离线播放”。旧的无 SHA-256 媒体需联网补齐校验元数据并重新保存。

服务端签发绑定家庭、用户、设备和媒体版本的 P-256 授权，有效期 7 天，客户端固定首次取得的服务器公钥。授权由既有 `auth_secret` 派生，因此部署必须保留该密钥；更换密钥后需要重新配对。已知设备撤销、无权限、待执行提醒、授权过期及时间回拨均不能用断网绕过。离线播放器使用无网络上游的数据源，字幕来自私有文件。

离线事件先入 SQLite。授权到期处截断记录并停止播放；容量不足不允许开始新的离线会话。恢复连接先上传事件，再拉取服务端进度；只有已确认的同会话序号或更新会话能替换本地进度。上传失败保留事件；冲突或授权不匹配显示待核验状态，不把内容接口的有效身份误判为离线记录错误。

## 验证与发布

自动化检查：

```sh
apps/server/.venv/bin/python -m pytest apps/server/tests -q
pnpm --dir apps/tv/web build
pnpm --dir apps/tv/web test
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home apps/tv/gradlew -p apps/tv :client:testDebugUnitTest :client:lintDebug
```

先发布服务端，再发布包含新版网页的 TV Shell。无需删除旧媒体数据；新增表在服务端初始化时创建。日常网页检查使用 `bash tools/run-tv-web.sh` 和 `http://127.0.0.1:5173/tv/`，不需要 Docker 或模拟器。

发布前仍需在真实电视验证 Android WebView / Bridge、原生播放及字幕、断网重启、授权到期、下载中断续传、切换绑定、长按遥控导航、播放返回和低存储空间。浏览器与 JVM 测试不能证明实际电视达到特定帧率。
